# Customer-360-Data-Platform
Overview

The Customer 360 Data Pipeline is an AWS-based data engineering solution designed to consolidate customer-related data from multiple daily CSV sources into a centralized, analytics-ready data warehouse.

The pipeline ingests data from customers, orders, website visits, and support tickets, processes and transforms the raw data using AWS Glue and PySpark, stores the curated datasets in Amazon S3, and loads them into Amazon Redshift using a Star Schema for efficient analytical querying.

The solution enables business teams to gain a unified view of customer behavior and derive insights such as Customer Lifetime Value, Churn Risk, and Purchase Patterns.

Key Components
Amazon S3 – Provides scalable storage for both raw and curated datasets. Raw files are preserved in the raw zone, while processed datasets are stored in the curated zone.
AWS Glue Crawlers – Automatically discover the structure and schema of incoming CSV files.
AWS Glue Data Catalog – Maintains centralized metadata and schema information for the datasets.
AWS Glue PySpark – Performs data transformation, cleaning, standardization, deduplication, and incremental data processing.
Audit Logging – Tracks pipeline execution and processing information to improve monitoring and data reliability.
Amazon Redshift – Stores the curated data in a dimensional Star Schema optimized for analytical workloads.
Analytical Views – Provide business-friendly datasets for customer analytics and reporting.
Data Processing

The ETL layer performs several important transformations:

Data Cleaning – Handles missing values, invalid records, inconsistent formats, and unwanted data.
Standardization – Applies consistent formats and data types across all source systems.
Deduplication – Identifies and removes duplicate customer and transactional records.
Incremental Loads – Processes only new or changed records instead of reprocessing the entire dataset.
Audit Logging – Maintains processing metadata such as load status, record counts, and execution details.
Analytics

The curated data is modeled in Amazon Redshift using a Star Schema, making it easier and faster to perform analytical queries.

The pipeline supports analytical use cases including:

Customer Lifetime Value (CLV) – Understand the total value generated by customers over their relationship with the business.
Churn Risk Analysis – Identify customers who may be at risk of leaving based on behavioral and transactional patterns.
Purchase Pattern Analysis – Analyze customer purchasing behavior, order frequency, spending trends, and product preferences.
Objective

The primary objective of this project is to build a reliable, scalable, and analytics-ready Customer 360 data platform that transforms raw operational data into trusted business insights while supporting incremental processing and data quality controls.

## Raw CSV Ingestion

The first Python component validates and uploads one dated source batch to the S3 raw zone. The uploader expects these files in a dated directory:

```text
data/raw/YYYY-MM-DD/
├── customers.csv
├── orders.csv
├── website_visits.csv
└── support_tickets.csv
```

### Setup

Create a virtual environment and install the project dependencies:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
```

Configure AWS credentials using the AWS CLI or the standard boto3 environment/profile configuration. The identity needs permission to upload objects to the target bucket.

### Validate Without Uploading

Use the dry run to validate headers, count rows, and print the target S3 keys:

```powershell
python -m customer360_ingestion --bucket customer360-example --dry-run
```

### Upload To S3

Run the same command without `--dry-run` once the target bucket and AWS credentials are ready:

```powershell
python -m customer360_ingestion --bucket customer360-example
```

By default, files are uploaded to `s3://<bucket>/raw/<date>/<filename>`. A different local batch or S3 prefix can be supplied with `--source-dir` and `--prefix`.

### Tests

Run the unit tests without AWS credentials:

```powershell
$env:PYTHONPATH = "src"
python -m unittest discover -s tests -v
```
